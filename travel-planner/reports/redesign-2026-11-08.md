# 여행잇 전국 여행 화면 개편

대상 저장소: hundol047/MY-AI-LAB. 기존 SCV-hacktoon 저장소와 배포 서버는 직접 변경하지 않았다.

## 화면

- 홈: 사진 헤더, 자연어·음성 입력, 직접 선택 폼. PC 두 열, 모바일 한 열.
- 결과: 일정 / 숙소 / 예산 / 여행 도우미로 분리. 일차별 일정과 지도는 같은 화면에 유지.
- 숙소: 실제 숙소 사진 카드 3개, 추가 숙소 더보기, 모바일 가로 넘김. 사진 누락·실패 시 대체 표시. 상세 요금 입력은 접힘.
- 일정 생성: 실제 계산을 유지하면서 단계별 연출 대기를 약 2초에서 약 0.2초로 축소.
- 전국: 17개 시·도 선택. 기존 강원 5개 권역을 유지하고 나머지 16개 시·도에 이름·좌표가 있는 시작 후보 1,056개 추가. 대표 출발점 주변 자료이며 각 시·도의 모든 시군구를 포함하지 않는다.
- 실제 영업시간이 없는 후보는 계획용 시간 범위만 사용하며, 영업시간 확인 완료로 표시하거나 가이드에서 확정 운영시간으로 답하지 않는다. 무장애 조건에는 자료상 휠체어 접근 가능 표시가 있는 전국 후보만 사용한다.
- 지역 밖 축제는 결과에서 제외. 공유 링크·캘린더·예약 날짜·객실·기존 무료 가이드 유지.

## 숙소 사진 API

`GET /api/lodgings?lat=37.8&lng=128.9`는 한국관광공사 숙박 자료를 조회한다. 서버의 `TOUR_API_KEY` 또는 기존 `BOPok_TOURAPI_KEY`를 사용하며 키를 브라우저로 보내지 않는다. 최대 6개, 10km 반경, 7초 제한, 30분 캐시, 동시 요청 제한. 사진과 위치 자료만 조회하며 실시간 객실 재고·최저가가 아니다.

API가 없거나 실패하면 저장된 실제 숙소 목록을 사용한다. 사진이 없는 숙소에 다른 숙소 사진을 붙이지 않는다. GitHub Pages에서는 서버 API가 없어 저장된 자료만 사용한다.

## 실행

Node.js 24 이상:

```sh
cd travel-planner
npm ci
npm start
```

기본 주소 `http://localhost:8080`. 로컬 개발 파일 `.local/`에 서비스 데이터가 저장된다.

Ubuntu + Docker:

```sh
bash travel-planner/scripts/deploy-linux.sh 8001 /etc/yeohaengit/server.env http://52.65.9.104:8001
```

별도 컨테이너 `my-ai-lab-web`과 볼륨 `my-ai-lab-data`를 사용한다. 기존 `yeohaengit-web`을 중지하지 않는다. 외부 접속에는 서버 보안 그룹에서 선택한 포트가 허용돼 있어야 한다. 이 작업에서는 실제 EC2 배포를 수행하지 않았다.

## 검증

- 기존 일정·음성·다국어·공유·예약·서비스 테스트.
- `npm run test:national`: 전국 일정·접근성·출발지 해석·공식 숙소 응답 및 사진 URL 검증.
- `TEST_APP_URL=http://127.0.0.1:8082 CHROMIUM_PATH=/usr/bin/chromium npm run test:browser`: 서버를 실행한 뒤 PC/모바일 주요 흐름 검증. Playwright와 Chromium 필요.
- 브라우저 테스트의 숙소 API·사진은 고정 응답을 사용한다. 실제 관광공사 응답·외부 지도 타일·숙박 예약 사이트의 실시간 상태는 운영 키와 외부 서비스 상태에 따라 달라진다.

전국 자료 출처와 범위: `public/NATIONAL-DATA.md`.
